## 插件自身的问题与产品缺口

1. **H1/H2 为确认的插件正确性缺陷。** 旧连接清理可能删除新端点；失败启动会改变既有待验收任务的中断归属。上一轮已复现，但该轮真实成员正常完成，没有证据表明它们在真实委派期间被触发。U1 为安装更新链路缺陷，该轮没有执行正式 update。详细触发及边界见 [缺陷报告](REMAINING-WORK-0.6.2-2026-10-14.md)。
2. **review 回执过大且重复。** `src/mcp.js:165` 直接返回 runtime.review 的完整任务，通用 `:44` 再把整对象 JSON 序列化。本轮前一步 verbose status 已读取完整证据，review 成功又收到 task/result/attempt.result/review 等重复结构。应默认返回 taskId/attemptId/status/verdict/退出和证据摘要，完整报告保留显式查询；缩小回执不能代替验收。
3. **中途观察缺乏可交接内容。** 本轮等待阶段主要看到 generic commandExecution 动作、阶段和时间，只有最终报告才收到两个具体发现。它是当前设计局限，不是动作记录错误，也不能因此开放原始命令/敏感载荷。若有实测收益，可增加有界发现摘要及证据定位，让队长更早开始复核；不能自动把中间发现标为确认或完成。
4. **主 Agent 仍需前台轮询和手工复核。** 这是当前已声明能力边界，本轮没有证明父聊天唤醒或后台自动交接。持续计时及 running 阶段不能当作有效进展；不建议仅增加调度框架来解决。
