## 结论

默认原生路线符合目标，继续保持短 skill。当前插件没有额外并行引擎；真正执行的是宿主原生子代理，skill 主要约束分工、上下文、写入边界和复核。当前证据支持“能协作、打包轻、可以请求不同强度”，尚不支持“对日常任务稳定提速或省钱”。

本轮确认一个 P2 便携性缺陷：源码 skill 为符号链接时，原生打包成功但产物仍引用外部文件。严格写链路的独占和单轮成员是明确设计限制，不能当作新发现的程序 bug，也不应带回默认入口。优先补场景选择、写入归属、短交接和轻量评测；不扩建调度平台。

## 缺陷、限制与测试盲区

### P2：原生包保留外部 skill 符号链接

位置：[src/plugin-package.js:37](../src/plugin-package.js:37)。`cpSync` 未设置解引用，遇到符号链接时复制链接；随后的摘要读取会跟随仍存在的外部目标，于是打包正常返回。默认包声称可搬迁、脱离来源后独立使用，但该路径不成立。

复现步骤：复制最小源码到临时目录，将 `skills/team/SKILL.md` 设为指向外部普通文件的符号链接；调用复制源码里的 `packNativePlugin`；检查产物 skill 的 `lstat`；删除外部目标，再检查可读性。实际结果：打包成功、产物为 symlink、删除目标后不可读。原仓库及正式缓存均未修改，临时目录已经清理。

建议最小修补：明确源码 skill 必须是普通文件并检查父路径，遇到链接拒绝并报错；若产品刻意支持源码链接，需验证目标边界并复制成普通文件，再验证产物独立可读。对应回归必须验证移除源后结果，不能只验证打包当下字节相同。

复现脚本与结果：[audit-checks.mjs](/Users/anshunli1/.codex/visualizations/2026/10/16/01a142a6-3115-7c21-9632-f029fdee1e94/plugin-audit/audit-checks.mjs)、[pack-checks-result.json](/Users/anshunli1/.codex/visualizations/2026/10/16/01a142a6-3115-7c21-9632-f029fdee1e94/plugin-audit/pack-checks-result.json)。暂未修复。

## 推理强度与模型选择

当前宿主工具声明直接支持模型和强度参数，已列出 Sol、Astra、Claude Sonnet/Opus 等可选标识及其支持强度，因此本轮无须读 UI 下拉或另起 App Server。声明可选不代表知道底层路由、价格或模型质量，也没有据此把 Sonnet 认定为低价模型。小模型试验继续后置。

推荐短规则：

1. 不开成员：单文件定位、几行局部改动、唯一串行阻塞、交接成本明显超过工作量。
2. low：路径明确、要求可机械验收的查询/提取/简单局部任务；先限定范围，再独立验收。不是把不确定任务藏到低强度。
3. high：跨组件流程、缓存与异步竞态、关键实现和独立审查的默认选择。
4. max：宿主明确支持且重要不确定性或高强度尝试未解决时使用，不默认给所有成员。尊重用户显式选择，不静默改变。
5. 记录请求的模型/强度；工具没有实际回执时写 unknown。低强度不等于小模型，不直接等于便宜或更快。
6. 验收失败后，先区分信息缺失、环境故障与推理问题；用现有成员补事实/修小缺口，需要升级时显式重派并说明，不无限重试。

本轮低/高成员都通过 `model='group/auto-gpt-6-1-sol'` 与 `reasoning_effort` 显式派发，已被宿主接受；max 仅在隔离决策函数中作为支持值验收，没有真实 max 推理调用，也没有小模型效果测试。

## 下一轮如何得到可比较的效率证据

使用同一个验收集、同一仓库快照与依赖，所有变体都以最终验收通过为结束点：

- A：单强模型/高强度完成全任务。
- B：裸原生子代理、相同模型和强度，无team skill。
- C：team skill、相同模型和强度，隔离skill分工规则的贡献。
- D：在C基础上按任务混合low/high/必要时max，隔离强度策略的贡献。

先在 S1、S2 各做一组小规模匹配任务，有资源边界后再重复及交换顺序，避免固定第二组热缓存；未运行的重复实验不冒充计划已通过。没有必要为本次审查立即进行付费长跑。

最小可选记录：总交付时间、首个可用结论、主审与修复时间、人工干预、正确率/严重错误、成员重读文件、工具调用数、并行执行窗口、队长工作/等待时间、请求与实际模型/强度、各方 token/费用及unknown。费用应包含队长、成员、失败与重试，不能只比成员；cached input属于input，不重复相加。固定等待轮询和“声明已开工”不等于有效并行。
