## 实测发现并修复

- 覆盖 inherited MCP 配置时使用了 TOML 引号；实际 App Server 将其当成键的一部分，线程创建失败。改为普通 dotted key，并对无法安全表达的名字拒绝启动；补协议回归和真实线程检查。
- 第一轮真实模型调用改写了验收条目，严格合同验证拒绝该结果。保留原文匹配规则，增加每个任务专属的 JSON Schema 枚举和原文复制指令；第二轮成功。不以放松验证掩盖问题。
- 在结果校验失败时持久记录有界的原始结果摘录，并标记是否截断，方便定位模型输出问题。

## 未完成和已知限制

- 桌面插件目录安装、自动打包 MCP 路径、父聊天唤醒：未验证。当前 skill 包装与 MCP 手工配置分开。
- 真实强模型复杂任务通过率、与单 Agent/原生子 Agent/OMX 的效率对比：未评测。当前 smoke 仅验证接入。
- 不支持代码修改、worktree、执行验证命令、自动集成、跨厂商和后台协调者。
- P0 由队长显式启动就绪任务；不自动派发整个 DAG。
- 不提供强制父会话文件隔离，只是不复制父聊天，并限制已知工具/沙箱；实际权限强制依赖宿主和系统。
- 一个工作区一个运行时；不支持两个聊天各自启动独立 MCP 实例共享同一状态库。
- 旧运行时崩溃且 child PID 仍存在时拒绝接管，避免重复执行或误杀；没有完整的孤儿进程身份机制。
- MCP 断开会关闭运行时；不会承诺断线后继续工作并主动通知。
- `qualified.evaluationReference` 是配置者的声明，尚未绑定自动评测系统。
