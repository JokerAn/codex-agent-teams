# 实施路线

优先级固定为准确率、完成效率、成本。保持一条本机链路；详细证据见 STATUS.md。

## 已实现：0.2.0 可用闭环

- 明确合同、必要上下文、依赖与验收条件；默认 expert，不静默降级。
- 官方 App Server 新线程、只读/写 worktree 沙箱、结构化结果与 host usage。
- SQLite 唯一 owner、attempt 迟到门禁、并发/截止时间/取消、崩溃不重放。
- 真实 Git 基线（含显式脏源快照）、每 attempt 独立 worktree、路径与内容审计。
- 显式命令合同、有上限原始日志、退出码/信号、超时/取消及退出确认。
- 写任务独立 expert 只读审查、队长逐项复核、准确文件/日志/patch 指纹门禁。
- 显式保守集成与源命令复验，保持 source index/HEAD；拒绝源 drift，不自动解决冲突或提交。
- 七个 MCP 工具、CLI 完整入口、skill、生产依赖插件封装；临时宿主安装与缓存验证。
- 真实 writer/reviewer/验证/集成/复验端到端已测，模拟与真实证据分开记录。

## 后续：有证据的改进

- P2 同任务/同基线/同验收质量与效率对照：单强模型、原生子 Agent、OMX。先测正确率、严重缺陷、耗时/返工/人工介入，再看费用；没有证据不降低模型能力。
- 更多 Git/平台/宿主版本矩阵；桌面 UI 操作、父聊天唤醒分别验收。
- 跨会话共享 owner、完整孤儿进程身份、执行环境快照只有实际需要时再扩展。
- 需要联网依赖安装、自动修复集成冲突或后台协调时，先定义单独权限/状态合同；当前不隐式启用。
- 界面/其他模型后端只根据实际需求增加，不预铺框架。
