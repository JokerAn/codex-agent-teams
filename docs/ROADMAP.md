# 实施路线

优先级固定为准确率、完成效率、成本。保持一条本机链路；详细证据见 STATUS.md。

## 已实现：0.2.0 可用闭环

- 明确合同、必要上下文、依赖与验收条件；默认 expert，不静默降级。
- 官方 App Server 新线程、只读/写 worktree 沙箱、结构化结果与 host usage。
- SQLite 唯一 owner、attempt 迟到门禁、并发/截止时间/取消、崩溃不重放。
- 真实 Git 基线（含显式脏源快照）、每 attempt 独立 worktree、路径与内容审计。
- 显式命令合同、有上限原始日志、退出码/信号、超时/取消及退出确认。
- 写任务独立 expert 只读审查、队长逐项复核、准确文件/日志/patch 指纹门禁。
- 显式保守集成与源命令复验，保持 source index/HEAD；拒绝源 drift，不自动解决冲突或提交。
- 七个 MCP 工具、CLI 完整入口、skill、生产依赖插件封装；临时宿主安装与缓存验证。
- 真实 writer/reviewer/验证/集成/复验端到端已测，模拟与真实证据分开记录。

## 已实现：0.2.1 正确性与离线回归

- 新 attempt 执行信息归属修补，失败/取消/无效结果回归；保留旧 attempt 历史与迟到门禁。
- 所有成员模式及独立 reviewer 统一核对实际 cwd，依据本机 schema；错误目录拒绝推理。
- 致命协议错误后释放缓冲、丢弃后续输出，保留进程组清理；多字节限额及持续输出回归。
- macOS/Linux × Node 24.0.0/24.x 离线 CI、源码覆盖率、生产封装与 SDK 检查；远程矩阵待执行。
- 版本 0.2.1，MCP/App Server 共用 package 元数据；138/138 本机回归与无推理宿主 smoke 通过，详见 STATUS.md。

## 已实现：0.2.2 运行可感知性

- team 前台技能约定启动/阶段/结束反馈与未委派说明；依赖实际工具记录，不承诺自动推送或宿主原生 UI。
- 无 owner 的只读状态观察，可与活 MCP 并存；overview 显示任务状态、阶段/耗时/证据摘要，未知旧字段不推测。
- 查看工具与运行 owner 的版本/来源分离，包内 build 摘要可追溯；仍需显式重装正式缓存。
- CLI 人类可读摘要和本地 HTML 快照，支持搜索/筛选/详情，不开启服务或后台执行；新增一个 status 核心模块，无依赖扩张。
- 147/147 最终本机回归、浏览器交互、真实临时缓存 overview 和独立复核通过；远程矩阵未验证，详情见 STATUS.md。

## 0.2.3：错误证据与恢复时间修补

- App Server run/probe 保留原执行错误与清理错误，单独清理失败仍拒绝成功，进程退出门禁保留。
- 恢复保留已有结束时间，另记恢复观察时间；成员、集成及命令结束未知时不伪造耗时，状态时间线明确标注中断。
- 新增双重失败、持久化/重派门禁、固定时钟恢复与真实 Git 集成崩溃回归；本轮验证结果见 STATUS.md。

## 已实现：0.3.0 用户确认模型分工

- 读取 Codex 真实可见模型和有效配置，新增 teams_models/CLI models，无推理、不展示完整配置。
- 官方 SDK 用户表单确认 expert/simple 分工；CLI start/run 提供交互确认；MCP/CLI 未确认不启动，重启重新确认，用户取消不默认同意。
- auto 仅在明确 simple、非 review 时用已确认轻量模型，复杂/不确定任务、独立审查和重试使用 expert；可显式指定 expert。每 attempt 保存确认与 reviewer 快照。
- 163/163 本机回归与实际临时宿主表单转发/取消门禁通过；宿主禁止交互时会直接 decline，桌面点击与真实模型分工效果待验收。当前队长模型仍由宿主选择。

## 0.4.0：目标绑定、偏好复用与任务预检

- 新任务绑定真实 checkout 身份；MCP 必填 expectedWorkspace，CLI 默认核对当前目录；状态显示实际目标。
- 用户可主动记住工作区模型分工，每次启动重新检查模型、强度、目标与策略；支持显式撤销。默认仍仅本次运行时。
- worktree 准备后、推理前检查验证程序及任务声明文件/Node require 依赖，记录解析来源；预检失败与执行阶段提供结构化原因和下一步。
- 验收结果见 STATUS.md；真实模型效果和跨产品对照不由离线回归替代。

## 后续：有证据的改进

- 按真实任务扩展已有预检与错误分类；不隐式安装依赖或预铺完整环境冻结。优先小规模同条件交付评测，确认收益后再考虑有界修复回合或并行写入。

- P2 同任务/同基线/同验收质量与效率对照：单强模型、原生子 Agent、OMX。先测正确率、严重缺陷、耗时/返工/人工介入，再看费用；用户确认的模型分工不等于质量/费用优势，不开启按价格自动降级。
- 更多 Git/平台/宿主版本矩阵；桌面 UI 操作、父聊天唤醒分别验收。
- 跨会话共享 owner、完整孤儿进程身份、执行环境快照只有实际需要时再扩展。
- 需要联网依赖安装、自动修复集成冲突或后台协调时，先定义单独权限/状态合同；当前不隐式启用。
- 界面/其他模型后端只根据实际需求增加，不预铺框架。
