## 后续：有证据的改进路线

- 按真实任务扩展已有预检与错误分类；不隐式安装依赖或预铺完整环境冻结。优先小规模同条件交付评测，确认收益后再考虑有界修复回合或并行写入。

- P2 同任务/同基线/同验收质量与效率对照：单强模型、原生子 Agent、OMX。先测正确率、严重缺陷、耗时/返工/人工介入，再看费用；用户确认的模型分工不等于质量/费用优势，不开启按价格自动降级。
- 更多 Git/平台/宿主版本矩阵；桌面 UI 操作、父聊天唤醒分别验收。
- 跨会话共享 owner、完整孤儿进程身份、执行环境快照只有实际需要时再扩展。
- 需要联网依赖安装、自动修复集成冲突或后台协调时，先定义单独权限/状态合同；当前不隐式启用。
- 界面/其他模型后端只根据实际需求增加，不预铺框架。
