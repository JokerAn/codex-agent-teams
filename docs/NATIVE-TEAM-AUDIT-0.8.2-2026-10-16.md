**性能判断**

默认 marketplace 只有5个文件、4,568字节，包含 skill、元数据和 marketplace 描述。没有外置 MCP、hooks、数据库、状态页、模型探测或 App Server；strict 源码不进入默认包。

Node v24.21.0/macOS arm64，本机直接打包函数首次约3.96ms，之后11次中位数1.92ms、P95 2.20ms；包含 Node 启动的5次 CLI build 中位数26.89ms。样本很小，P95使用最近秩；不是模型推理、插件发现或协作总交付耗时。当前证据支持默认包运行负担很小，无法证明 team 比裸原生、单 Agent 更快或更省钱。

只有在同一需求、仓库快照、独立验收下比较单强模型、裸原生、team 同档位与 team 混合档位，并记录最终验收完成时间及真实用量，才能判断收益。历史微型增强也没有证明多开成员有提速，因此不要为几行明确修复自动开队，也不要给插件添加虚假的速度或费用估算。

**确认的问题与最小处理**

1. **P2：安装验收漏过额外 skill。** [scripts/update.js](../scripts/update.js:38) 只核对固定名单，native 检查另拒绝 `src` 和 `node_modules`，没有对整个实际 skill 集合做比较。候选只有 `team`，受控安装缓存增加 `skills/old-runtime/SKILL.md` 后仍返回更新成功。队长使用真实文件复制的独立复现器再次确认，并包含干净安装正对照。manifest 将 `./skills/` 作为发现根，所以多余指令值得拒绝；本轮没有启动官方宿主，不能声称它已经实际加载，也不能声称官方 CLI 正常安装一定残留。最小修复是校验 native 文件/skill 集合与候选一致、拒绝多余入口及链接，不需要新增运行时或全量扫描业务仓库。
2. **P2 测试覆盖缺口：旧新内容没有实际切换。** [tests/update.test.js](../tests/update.test.js:25) 从新候选复制初始缓存，再复制为旧来源；模拟 `plugin add` 改元数据，没有按当前 marketplace 实际复制文件。旧元数据虽标0.5.2，内容仍是当前版本。它能检查拒绝、顺序和漂移，但对跨版本替换与恢复的证明较弱。队长补了独立受控探针：构造不同字节的0.8.1来源及0.8.2候选，实际删除/复制缓存；更新通过，复制新缓存后注入失败也能恢复旧版字节。此结果补充了本次证据，尚未修改仓库正式测试，也没有证明更新实现已坏。建议把这种有区别的fixture收进现有回归；strict→native仍需单独覆盖。
3. **可操作性建议：把上下文规则落到宿主参数。** [skill](../skills/team/SKILL.md:10) 已要求默认不复制全聊天，但当前 spawn 参数默认 `fork_turns=all`。本轮显式 `none`，没有观察到全量继承失误。建议只补一句“宿主支持时显式关闭父历史继承”，不新增上下文裁剪器、模型确认流程或任务数据库。

队长还检查了已存在的悬空输出链接：打包返回 `ENOTDIR`，原链接保留，没有复现覆盖用户文件，因此不列为缺陷。旧版本链接便携性、恢复来源预检和 `--binary` 问题已经有修补，不重复报成当前新问题。
